    DDD capabilities to add

    Everything else in the block is existing DDD: block anatomy, block actions, toolbar buttons, DDDTable, chart palette, status tokens and full screen. These seven are what the web needed and DDD does not have yet.

    • Connector line vocabulary

      The web needs five kinds of connection that stay distinct without colour. Today it borrows the status line styles (solid, dashed, dotted), but in DDD those mean answered, revealed and incorrect. Proposed: --ddd-connector-* tokens for stroke width and dash pattern per meaning (relationship, contract, membership, credit, emphasis), so a dotted line never reads as "incorrect".

    • Animated connectors

      Two motions that belong in the #3221 library rather than in this element: draw-in (stroke-dashoffset from 1 to 0, used here as the single motion moment) and flow (dots marching along a dotted line, for showing direction such as PRAW → Future Traveler). Each needs a duration token and a built-in reduced-motion stop. The prototype draws in only; flow is off until DDD has it.

    • Node shapes

      Circle, hexagon, rounded tile, cylinder, stadium and subroutine frames, each with an icon box and a monogram fallback. There is no DDD shape primitive; a small set of SVG path tokens or a ddd-shape helper would let the graph, cards and badges share them.

    • Reader-facing search combobox

      .hax-ui-input is editor-only. Readers need a DDD search field with a results listbox, group headings and an active-option style. It is styled with tokens here.

    • Reader-facing toggle group

      Tour or Timeline and the layer switches use .ddd-block-action.has-text with aria-pressed, which works, but there is no grouped style (shared border, joined ends). .hax-ui-seg exists for editors only.

    • Lifecycle status pill

      Released, pre-release, planned and legacy reuse the answered, revealed and disabled status tokens. That works visually, but they are answer states, not release states. Proposed: a ddd-status-pill with lifecycle tokens, which is also all the release check needs to be pure DDD.

    • Pan and zoom viewport

      Drag, pinch, Ctrl + scroll, zoom buttons and fit to view are hand-written. A DDD viewport helper (and the corner zoom control as a pattern) would serve this element, maps, image-compare and large diagrams.

    Graph source

    Each web is two files: Mermaid for structure (renders as-is on GitHub) and JSON for descriptions, links, releases, evidence, tours and years. The editor shows the web you have open. Sub-webs reuse ecosystem nodes by id, as portals.

    Motion vocabulary

    Nine CSS keyframe motions cover every node. They are the icon library for #3221, previewed here on hover or focus; inside the instructional block they do not play, because the block keeps to one motion moment (connections drawing in during Play). All are off under reduced motion. The library proposal is in #3221.

    Icons are the SVGs from @haxtheweb/hax-iconset and @haxtheweb/simple-icon 26.8.0, except the two new marks. The Future Traveler is world-traveler-15 from haxtheweb/art. People come from the hax-lab README, WINS.md and WORLDVIEW.md. Organizations and people show monogram placeholders; each takes a logo= URL in the source. The shipped hax:file-ai and hax:file-html SVGs hard-code white and black fills; their letters are knocked out here.
